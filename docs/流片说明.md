# to2610-smt 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

超线程的单核 Linux 系统芯片，面向 ECOS 2610 班车：一个 KianV 核，两个硬件线程。核里只有一套状态机、数据通路与访存口，体系结构状态每个线程一份；软件看到的与 `to2610-smp` 一样，是 0 号、1 号两个 hart。片上其余部分取自 `to2610-smp`：两个 CLINT、核间那一页、存储与外设。1 号线程没放开时，整颗与 `to2610-kvc` 一样，同一份镜像照样起得来。

本仓自己写的只有 `patch/smt.patch`，由 `patch/mkpatch.py` 生成：把 `to2610-smp` 的两个核加总线仲裁换成一个带两套线程状态的核。核的子模块不动。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 处理器 | 一个 KianV 核，两个硬件线程，RV32IMA、Sv32 | `mhartid` 分别是 0 与 1 |
| 每个线程一份的 | 通用寄存器、PC、上一条指令的 PC、CSR 与特权级、中断的判定、地址转换、LR 的预留 | 状态机、ALU、乘除法器、访存口共用 |
| 地址转换 | 每个线程各有 `satp` 与指令、数据两个 TLB，各 16 项 | 两个线程可以各在各的地址空间里 |
| 轮转 | 每条指令做完换另一个线程 | 一条指令从取指到写回不换人，九条 AMO 因此是原子的 |
| 睡眠 | 线程执行 WFI 而没有开着又挂起的中断时，轮转跳过它 | 它的中断一来就排回去；每跳过 63 次也轮到一次 |
| LR 与 SC | 预留按物理地址记，每个线程一条；另一个线程写了同一个字就作废 | SC 写的不是预留的那个字也写不成 |
| 存储与外设 | 同 `to2610-kvc` | 片外 SDRAM 32 MiB 与 SPI Flash，串口 0、SD 卡口、SPI 网卡口、1 位 GPIO，两个线程都看得见 |
| 核间中断与计时器 | 每个线程一个 CLINT：`0x0200_0000` 与 `0x0300_0000` | 两边的 `mtime` 是同一个计数，每微秒走一格；两个线程读 `time` 也是这个数 |
| 外部中断 | PLIC 只进 0 号线程 | 1 号线程的机器态外部中断接核间那一页的门铃 |
| 1 号线程的起停 | 核间那一页的 `RUN` | 复位后不动；放开后从 `0x8000_0000` 起 |

### 两个线程怎么共用一个核

KianV 是多周期的核：一条指令从取指走到写回要十来拍，状态机回到取指就是一条指令做完了。线程号只在这一拍变，所以一条指令的中间状态（指令寄存器、ALU 的结果、乘除法器、AMO 暂存的数）不用分线程，只有跨着指令留下来的才要每个线程一份：

| 状态 | 怎么分 |
|:--:|:--:|
| 通用寄存器 | 寄存器堆加一位地址，64 项，线程号做最高位 |
| PC | 两个寄存器，写使能带线程号 |
| 上一条指令的 PC | 同上。跳到没对齐的地址，要到取下一条时才陷入，报的是跳的那一条；中间夹着另一个线程的一条指令 |
| CSR、特权级、中断的判定 | 整个模块例化两遍，写与事件只给现在跑的那个线程，读出按线程选 |
| 地址转换 | 整个模块例化两遍，请求只给现在跑的那个线程 |
| LR 的预留 | 核里的那一条例化两遍，另在访存口上按物理地址记一张两项的表 |

中断在译码那一拍判，看的是现在这个线程自己的那一份，所以两个线程各收各的中断。

### 睡与醒

上游的 KianV 把 WFI 当空指令。这一颗多记一位：线程执行了 WFI，而它开着的中断里没有挂起的，就算它在睡。轮转跳过睡着的线程，另一个线程每条指令都接着跑，速度接近单核。睡着的线程有中断挂起（`mip` 与 `mie` 相与不为零，不看全局使能）时立刻排回轮转。

WFI 许无故返回，所以睡着的线程每跳过 63 次也轮到一次：拿 WFI 当停顿、靠轮询内存等另一个线程的程序不会被饿死。两个线程都在睡时现在跑的那个接着跑。

### 原子指令在两个线程下怎么成立

- AMO：读与写在同一条指令里，中间不换线程。
- LR：访存口上记下这个线程读的是哪个字，按物理地址。另一个线程写了同一个字（普通的写、AMO 的写、写成了的 SC 都算），这条预留作废。
- SC：轮到它写的那一拍，预留已经作废或者地址不是预留的那个字，这一笔不上总线，晚一拍回应答并告诉状态机没写成，目的寄存器得 1。SC 之后预留一律放掉。

### 两个线程怎么起

复位后只有 0 号线程在跑，启动流程同 `to2610-kvc`：从 Flash 的 `0x2010_0000` 就地执行引导程序，它把载荷搬进 SDRAM 再跳到 `0x8000_0000`。往 `0x4004_0004` 写 1 放开 1 号线程，它的复位地址也是 `0x8000_0000`，两个线程进的是同一个入口；程序开头读 `mhartid`，按编号分栈、分路。

往 `RUN` 写 0 收回 1 号线程：它的 PC、CSR 与地址转换回到复位值，轮转不再给它拍子。再写 1，它从头来。

## 寄存器

`to2610-kvc` 的地址图原样保留（见它的流片说明）。这一颗新加的与 `to2610-smp` 相同，只有标识不同：

| 地址 | 含义 |
|:--:|:--:|
| `0x0300_0000` | 1 号线程的 `msip`：第 0 位写 1，它收到机器态软件中断 |
| `0x0300_4000` | 1 号线程的 `mtimecmp`，64 位，低字在前 |
| `0x0300_BFF8` | `mtime`，只读，与 `0x0200_BFF8` 是同一个计数 |
| `0x4004_0000` | 核间那一页的标识，只读，`0x534D5431`（"SMT1"） |
| `0x4004_0004` | `RUN`：第 0 位放开 1 号线程，复位为 0 |
| `0x4004_0008` | `BELL_A`：写 1 的位置起，读回挂着的；挂着就经 PLIC 的 26 号报给 0 号线程 |
| `0x4004_000C` | `ACK_A`：写 1 的位把 `BELL_A` 清掉 |
| `0x4004_0010` | `BELL_B`：同上，挂着就是 1 号线程的机器态外部中断 |
| `0x4004_0014` | `ACK_B`：写 1 的位把 `BELL_B` 清掉 |
| `0x4004_0018` | `MSG_A`：一个字，约定由 1 号线程写给 0 号线程 |
| `0x4004_001C` | `MSG_B`：一个字，约定由 0 号线程写给 1 号线程 |

0 号线程的 `msip` 在 `0x0200_0000`，两个线程互发核间中断就是往对方的这一位写 1。

## 板级连接

引脚与 `to2610-kvc` 逐位相同，kvc、amp、smp、smt 四颗用同一块底板：payload 的 0 到 53 位（串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO），接法见 `to2610-kvc` 的流片说明。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

- 时钟 50 MHz。
- 串口 0 是默认的调试输出与控制台，115200，两个线程共用。
- 复位：按住复位时全部 payload 脚高阻，烧录器夹上 Flash 就能在板写。

## 测试说明

整片测试的测试台 `tb.cpp` 来自黑盒仓，跑在 Verilator 上，带 SDRAM、Flash、串口的引脚级模型；被测的是 `ran asic` 出的那份交付文件。

| 用例 | 测什么 |
|:--:|:--:|
| hello、periph、isa、arch-test、boot | `to2610-kvc` 的五段原样再跑：1 号线程没放开时，这一颗与单核的那一颗一样 |
| rtos | `to2610-kvc` 的 FreeRTOS 冒烟原样在 0 号线程上跑：三个任务、队列、互斥量、节拍与抢占 |
| image、linux | `to2610-kvc` 的单核 Linux 镜像先在 QEMU 上起到 shell；同一份镜像在这一颗上从 Flash 引导到 shell、跑那组命令。1 号线程没放开，0 号线程上起的是一份单核的 Linux。仿真要几个小时，流水线上分几棒接力，每棒从前一棒的断点接着跑 |
| image-smp、linux-smp | `to2610-smp` 的两核镜像原样（设备树两个 hart、各自的 CLINT，内核开 SMP，OpenSBI 的平台补成两个 hart）先过 QEMU，再在这一颗上从 Flash 起到 shell：固件在冷启动时写 `RUN` 放开 1 号线程，内核把它带起来（`smp: Brought up 1 node, 2 CPUs`）；`/proc/cpuinfo` 里两个处理器；`apptest` 十项（fork、管道、信号、共享映射、四个线程的互斥锁与原子加等）全过；两个忙循环各占一个线程；核间中断两边都有。另一串接力 |
| threads | riscv-tests 在两个线程上各跑，共 238 次，三种轮法：0 号线程跑测试、1 号在入口转圈，两个线程一人一条指令地轮；1 号线程跑测试、0 号睡着；1 号线程跑测试、0 号不停地改自己的寄存器、CSR 与内存并做自己的 LR/SC。1 号线程上不跑 `mcsr`，它测的就是 `mhartid` 读到 0 |
| smt：编号 | 0 号线程读 `mhartid` 得 0；放开 1 号线程，它从同一个入口进来，报回的是 1 |
| smt：一个线程时的 SC | 有预留写得成；没预留写不成、存储不变；预留的是另一个字也写不成，而且这一次把预留用掉了 |
| smt：直接加 | 两个线程各把同一个数读出来加一再写回两百次，结果必须少于四百。不丢数说明两个线程没有真的在抢，下面三项就什么也证明不了 |
| smt：`amoadd`、自旋锁、LR 与 SC | 各加两百次，都得四百；等锁的次数、写不成重来的次数都不能是零 |
| smt：各开各的页表 | 两个线程各建一张页表，把同一个虚地址映到不同的物理页，同时各写各读两百次：读回的都是自己写的，按物理地址看各落在各的那一页 |
| smt：预留跨线程 | 0 号线程 LR 之后 1 号写同一个字，SC 写不成；1 号写的是别的字，SC 照样写成；1 号只是预留了别的字，SC 也照样写成 |
| smt：核间中断与计时器 | 两个方向各发一次核间中断；1 号线程设自己的 `mtimecmp`，中断来一次 |
| smt：`time` | 1 号线程读到的 `time` 夹在它前后两次读 `mtime` 之间：放开之后一次，收回再放开之后再一次 |
| smt：睡与醒 | 1 号线程睡着（WFI）时，0 号线程同样时间里转的圈数至少是它忙着时的一倍半；发核间中断给睡着的 1 号，一百微秒里应到；1 号拿 WFI 轮询内存里的一个数、没有中断会来，0 号写了那个数它也等得到 |
| smt：收回与再放开 | `RUN` 写 0 之后 1 号线程的计数不再走；再写 1，它从头来、再报一次编号 |

设计的变异（任务 `design-faults`）另跑：把一处改错、重出 `.v`，管这一处的那一句必须红。十二处：通用寄存器不分线程、PC 不分线程、上一条指令的 PC 不分线程（由 `ma_fetch` 来红）、CSR 的写不分线程、中断线不分线程、两个线程的地址转换用同一个 `satp`、另一个线程写了预留的字而预留不作废、没有预留的条件写照样上总线、核里记的预留地址不分线程、WFI 之后不让出、睡着的线程中断来了不排回去、睡着的线程不定期轮到。

## 局限

- 同 `to2610-kvc` 的各条：缓存旁路、主频固定 50 MHz、没有 JTAG。
- 两个线程都在忙时一人一条指令，各自比单核慢一半上下。
- 外部中断只进 0 号线程；PLIC 没有 1 号线程的上下文。
- TLB 每个线程 16 项，`to2610-kvc` 是 32 项。
- 预留按字记，一个线程一条。开着虚存时取页表的读也会改写它，随后那一次真正的读再盖回来；LR 在取页表之后缺页的话，留下的是页表项的地址，随后的 SC 写不成。
- 1 号线程的复位地址固定是 `0x8000_0000`，放开它之前那里要已经有程序。
